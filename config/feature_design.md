# Daily Routine Bot 기능 설계

작성일: 2026-08-25

## 사용자 흐름

1. 사용자가 Telegram에서 `/start`를 보낸다.
2. 봇은 현재 대화방을 등록하고 도움말을 보낸다.
3. 봇은 KST 기준 현재 시각과 요일을 확인한다.
4. 아직 답변되지 않았고 조건을 만족하는 질문만 발송한다.
5. 질문이 발송되면 pending 상태로 저장한다.
6. 사용자의 다음 일반 메시지를 pending 질문의 답변으로 기록한다.
7. 선택형 질문은 Telegram reply keyboard와 번호 입력을 모두 지원한다.
8. 사용자는 `/today`, `/week`로 기록을 조회한다.

## 스케줄 규칙

스케줄은 `config/routine_schedule.json`의 `questions` 배열로 정의한다.

필수 필드:

- `field`: 저장 필드명
- `label`: 사용자에게 보여줄 항목명
- `weekdays`: 발송 요일
- `message`: 질문 문구

선택 필드:

- `time`: 고정 발송 시각
- `options`: 선택형 답변 목록
- `requires`: 선행 답변 조건
- `dynamic_time_from`: 다른 답변값에서 발송 시각을 계산할 필드
- `dynamic_time_preference`: 시간 파싱 보정값

## 조건부 질문

`requires`는 선행 답변에 따라 질문 발송 여부를 결정한다.

현재 조건:

- `work_plan=출근`일 때만 출근시간, 퇴근 예정시간, 퇴근 확인 질문을 발송한다.
- `leave_confirm=아니오`일 때만 연장근무 이유를 질문한다.
- `alcohol=예`일 때만 음주량을 질문한다.

출근하지 않는 날, 예정대로 퇴근한 날, 음주하지 않은 날에는 불필요한 후속 질문을 생략한다.

## 동적 퇴근 확인

퇴근 확인 질문은 고정 시간이 아니라 `planned_leave_time` 답변값을 기준으로 발송한다.

지원 입력 예:

- `18:00`
- `18시`
- `오후 6시`
- `6시`

퇴근 예정시간은 저녁 시간으로 해석하는 것이 자연스러우므로 `6시`처럼 오전/오후가 없는 1-11시 입력은 오후로 보정한다.

## 중복 질문 방지

다음 경우에는 자동 질문을 보내지 않는다.

- 오늘 이미 같은 `field`가 저장된 경우
- 오늘 이미 같은 질문을 발송한 경우
- 봇이 `/pause` 상태인 경우
- 선행 조건을 만족하지 않는 경우
- 이전 질문이 아직 pending 상태인 경우

## 명령어

- `/start`: 현재 Telegram 대화방 등록
- `/help`: 도움말
- `/fields`: 수동 기록 가능한 항목 표시
- `/today`: 오늘 기록 조회
- `/week`: 최근 7일 기록 조회
- `/record <field> <value>`: 수동 기록
- `/skip`: 현재 pending 질문 건너뛰기
- `/cancel`: 현재 pending 질문 취소
- `/cancle`: 오타 대응용 취소 alias
- `/pause`: 자동 질문 일시 중지
- `/resume`: 자동 질문 재개
- `/status`: 봇 상태 확인

## 데이터 저장

SQLite `routine_entries` 테이블에 날짜, 필드, 라벨, 값, 입력 경로, 질문 시각, 답변 시각을 저장한다.

같은 날짜와 같은 필드의 값은 upsert 방식으로 갱신한다.
